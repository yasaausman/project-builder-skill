# LESSONS.md — what past projects taught

Cross-project memory for project-builder. Read at the start of IDEATE, RESEARCH and BUILD;
written whenever a choice turns out wrong or painful, an estimate misses, a verdict proves wrong,
or the user corrects the approach, plus a retro when a project wraps. See SKILL.md →
"Memory & learning".

**Format.** One rule per bullet, written as an instruction for next time; dated evidence under it,
newest first.

```markdown
- **<Rule to follow next time>** · seen N×
  - YYYY-MM-DD · <project> · <what happened>
```

**Bounds.** At most 10 rules per category (40 total).
- Same lesson again → add a dated line under the existing rule and bump `seen`; never a duplicate rule.
- Category full → merge near-duplicates first, then drop the least useful rule that is `seen 1×`
  and older than ~6 months.
- Keep each evidence line to one sentence; keep at most 3 evidence lines per rule (drop the oldest).
- `seen 2×` or more → propose a SKILL.md patch (needs approval). Once applied, mark the rule
  `→ in SKILL.md (YYYY-MM-DD)`; it can be removed at the next prune.
